# packages/api-schema

`openapi.yaml` is the single HTTP contract between the backend and the frontend. The backend writes it (`cd apps/backend && .venv/bin/wise-workbench openapi --yaml --out ../../packages/api-schema/openapi.yaml`) and its test suite fails when the committed file differs from the generated document (drift check). The frontend regenerates `generated/schema.d.ts` from it (`cd apps/frontend && npm run generate`) and validates its mocks against it in the contract tests; `generated/index.ts` adds readable type aliases. Formats worth knowing: slice keys are JSON arrays (`["companyID_0000","Packaging"]`) and the slice-detail path parameter is that string URL-encoded; the `slicing` query parameter is the run's slicing id made of case attribute (column) names joined by `+`; backlog rows carry the library's column names plus the plain-language fields `kind`, `kind_reading`, `dominant_layer_name`, `top_constraint*`, `n_ranked` and `reading`.
